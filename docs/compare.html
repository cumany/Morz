打勾表示 Morz 默认有、开箱可用，不是每个维度都强过所有竞品。

先给结论：

  • 只想纯写作、最看重文字排版：Typora 仍然很稳。
  • 想把笔记做成插件化知识库、愿意折腾生态：Obsidian 仍然是首选。
  • 主要用大纲和思维导图整理思路：幕布更直接。
  • 想要所见即所得、文件归自己，同时表格/查询/导出开箱能用：Morz 值得试。

四、各自强在哪

Obsidian

强在生态和可组合性：

  • 插件、主题、社区教程数量最多
  • 双链、图谱、Dataview、Canvas 等知识库玩法成熟
  • 文件仍在本地，长期可迁移

代价是：

  • 想得到完整体验，通常要装插件、调设置
  • 不同插件质量参差，出问题要自己排查
  • 移动端和同步是另一套成本

适合：愿意折腾、需要插件生态、把笔记当长期知识系统的人。

Typora

强在单点写作体验：

  • 打开就写，排版干净
  • 所见即所得成熟，干扰少
  • 买断、无需账号、文件本地

代价是：

  • 没有双链、反链、查询、插件生态
  • 文档一多，组织能力主要靠文件夹和搜索
  • 表格、复杂导出不是它的主战场

适合：主要写文章、报告、草稿，不需要知识库能力的人。

幕布

强在大纲和思维导图：

  • 先用层级把想法列出来，再一键转脑图
  • 云端同步、分享和团队空间省事
  • 适合会议纪要、课程笔记、方案拆解

代价是：

  • 不是本地 .md 文件工作流
  • 不以双链、Dataview、插件/主题生态为核心
  • 想长期做知识库，迁移和可组合性不如本地工具

适合：主要用大纲/脑图整理思路、需要云端共享的人。

Morz

强在本地优先 + 开箱即用：

  • 所见即所得，同时保留 Markdown 源码可编辑
  • 文件是普通 .md，不锁库、不需要账号
  • 双链、反链、块引用、标签、搜索、图谱内置
  • 表格支持公式、填充、选区、整格撤销
  • Dataview 查询内置，不用先装插件
  • HTML / PDF / Word 导出开箱可用
  • 图片/表格可视化操作、画廊和自动整理
  • 桌面、Android、PWA 覆盖面较完整
  • 有插件 SDK、主题市场和公开 registry，但不追求兼容 Obsidian 插件

适合：想要 Obsidian 的部分知识库能力，但不想装一堆插件；又想要 Typora 那种直接写的感觉；同时希望文件始终是本地 .md。

五、其他选择

场景 更合适的选择
大纲、思维导图、云端分享 幕布
本地 outliner、块引用、查询 Logseq
云端协作、数据库视图、团队共享 Notion
开发者、键盘流、Git、任意语言插件 VS Code + Markdown 扩展
纯写作、排版、买断 Typora
插件化本地知识库 Obsidian
本地所见即所得 + 内置查询/导出 + 免账号 Morz

六、从 Obsidian / Typora / 幕布迁过来

  • 文件：Obsidian/Typora 直接用 Morz 打开原来的文件夹，.md 原样保留；幕布内容需要先导出。
  • 双链：[[页面]]、[[页面|别名]]、[[页面#标题]]、[[页面#^块id]]、![[嵌入]] 原生支持。
  • 主题：可以导入 .css 主题；Blue Topaz 的设置项也有兼容层。
  • 插件：Obsidian 插件不能直接运行，需要用 Morz SDK 重写；迁移前先确认关键插件是否有替代。
  • Dataview：常用 TABLE / LIST / TASK、FROM、WHERE、SORT、GROUP BY、LIMIT 支持；复杂脚本先试跑再迁移。
  • 大纲：内置 section fold 与大纲视图，长文可以折叠到章节；通用脑图仍建议用幕布 / Logseq。

七、Morz 的目标

写作手感超过 Typora，知识管理超过 Obsidian，重量保持在它们的十分之一。

你更在意 更合适的工具
只写单篇，不需要知识层 Typora
插件生态，愿意自己搭环境 Obsidian
大纲、脑图、思维导图 幕布 / Logseq
写作手感、知识管理、轻量，一个工具全要 Morz
