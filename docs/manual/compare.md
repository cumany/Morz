# 和 Obsidian、Typora、幕布对比

> 这页不是“参数越大越好”的发布会 PPT，也不靠贬低别人卖自己。
> 对比只写能验证的能力差异；功能和价格会变，以 [Obsidian](https://obsidian.md)、
> [Typora](https://typora.io)、[幕布](https://mubu.com) 和当前版本官网为准。
> 整理时间：2026-11。

## 一眼看懂 Morz

| 用户最在意的事 | Morz | 一句话 |
|---|---|---|
| 文件归自己 | ✅ | 普通 `.md`，不登录也能打开 |
| 打开就写 | ✅ | 实时预览；光标进入元素才露源码 |
| 读和写不割裂 | ✅ | 编辑、阅读、导出使用同一套 Markdown 语义 |
| 双链 / 反链 / 块引用 | ✅ | 本地知识库的基本盘 |
| 图片 / 表格能直接改 | ✅ | 图片对齐/宽度/图注/画廊；表格公式、填充、整格撤销 |
| 笔记能当数据查 | ✅ | 内置 Dataview 子集 + `dataviewjs` |
| 插件 / 主题能扩展 | ✅ 起步 | 自有 SDK + 公开 registry；不兼容 Obsidian 插件 |
| 工作区能分开 | ✅ | 文件夹工作区；布局/会话独立，偏好设置是全局的 |
| 大纲整理 | ✅ | 每日笔记大纲：下钻、折叠、列表约束 |
| 能交差 | ✅ | HTML / PDF / Word；PDF 页码/TOC/书签，Word 大纲/画廊/脚注 |
| 桌面轻量 | ✅ | Tauri + Rust 文件层，不是 Electron |
| 多端可用 | ✅ | 桌面 + Android + PWA；iOS 走 PWA |
| 免费起步 | ✅ | 本地功能免费，不依赖账号或云 |

> 打勾表示“Morz 默认有、开箱可用”，不是每个维度都强过所有竞品；不擅长的部分见第五节。

先给结论：

- **只想纯写作、最看重文字排版**：Typora 仍然很稳。
- **想把笔记做成插件化知识库、愿意折腾生态**：Obsidian 仍然是首选。
- **主要用大纲和思维导图整理思路**：幕布更直接。
- **想要所见即所得、文件归自己，同时表格/查询/导出开箱能用**：Morz 值得试。

## 一、写作与编辑

| 能力 | Morz | Obsidian | Typora | 幕布 |
|---|---|---|---|---|
| 核心形态 | 本地 Markdown 文档 | 本地 Markdown 知识库 | 本地 Markdown 编辑器 | 云端大纲 / 思维导图 |
| 写作方式 | 实时预览；光标进入元素才露出源码 | 实时预览 / 源码双模式，部分块仍是源码形态 | 所见即所得标杆 | 大纲块编辑 |
| 源码与阅读一致性 | 同一份 `.md`；阅读、编辑、导出走同一套 Markdown 语义 | 以源文件为准，实时预览/阅读可能有细微差异 | WYSIWYG 与源码模式 | 无 Markdown 源码层 |
| 大纲 / 思维导图 | 每日笔记大纲：下钻、折叠、只允许列表 | 大纲面板；不以大纲为核心 | 无专门大纲/脑图 | **强项**，可一键思维导图 |
| 双链 / 反链 / 块引用 | 原生支持 | 强项 | 无原生双链 | 不以双链为核心 |
| 图片 / 表格可视化操作 | 图片工具条、对齐/宽度/图注、画廊；表格公式、填充、选区、整格撤销 | 基础表格；复杂图片/表格能力靠插件 | 基础图片/表格 | 基础 |
| 编辑 / 阅读 / 导出 | 同一渲染链；导出会按 HTML/PDF/Word 分页适配 | 模式较多，导出依赖打印或插件 | 桌面内一致 | 云端编辑与导出 |

## 二、知识与数据

| 能力 | Morz | Obsidian | Typora | 幕布 |
|---|---|---|---|---|
| 查询 / Dataview | 内置 DQL 子集 + `dataviewjs` | 社区 Dataview 插件，生态完整 | 无 | 无内置查询 |
| 笔记就是数据 | frontmatter/行内字段/任务进入索引，可查询 | frontmatter + Dataview 生态 | 无 | 大纲结构本身 |
| 原生插件生态 | 自有 SDK；内置插件 + 第三方起步；**不兼容 Obsidian 插件** | 社区插件/主题极丰富 | 无插件 | 以模板为主，无原生插件生态 |
| 主题生态 | 内置主题 + 主题市场（含 Blue Topaz） | 社区主题极丰富 | CSS 主题 | 内置模板/主题 |
| 共享主题 / 插件 | 公开 registry，可安装插件与主题 | 官方社区市场 | 主题文件分享 | 模板/团队空间 |

## 三、工作区、平台与工程

| 能力 | Morz | Obsidian | Typora | 幕布 |
|---|---|---|---|---|
| 文件模型 | 本地文件夹里的 `.md` + 附件 | 本地 Vault | 打开本地文件夹 | 云端文档 |
| 工作区机制 | 文件夹工作区、多 tab、每个工作区独立会话/面板布局 | Vault 切换 | 打开文件夹 | 云端文件夹 / 团队空间 |
| 工作区独立设置 | 布局/会话独立；偏好设置为全局 | 布局随 Vault；部分设置靠插件 | 全局设置 | 云端空间设置 |
| 同步 / 账号 | 当前无内置云同步，本地使用不需要账号 | 官方 Sync（付费）；本地不需要账号 | 无内置同步，无需账号 | 原生云端，通常需要账号 |
| 移动端 | Android + PWA；无原生 iOS | Android / iOS | 无 | Web / 客户端 |
| 轻量 / 运行架构 | Tauri + WebView，Rust 负责桌面/文件层；编辑渲染仍是 CM6 | Electron | Electron | Web / 云端 |
| 价格 | 免费使用（内测），本地核心离线可用 | 个人免费；Sync / Publish 付费 | 一次性付费，提供试用 | 免费 + 会员 |

> “Rust 速度”指桌面壳与文件系统层（不是 Electron）；编辑器核心是 WebView 里的 CodeMirror，不代表所有操作都更快。

## 四、各自强在哪

### Obsidian

强在**生态和可组合性**：

- 插件、主题、社区教程数量最多
- 双链、图谱、Dataview、Canvas 等知识库玩法成熟
- 文件仍在本地，长期可迁移

代价是：

- 想得到完整体验，通常要装插件、调设置
- 不同插件质量参差，出问题要自己排查
- 移动端和同步是另一套成本

**适合**：愿意折腾、需要插件生态、把笔记当长期知识系统的人。

### Typora

强在**单点写作体验**：

- 打开就写，排版干净
- 所见即所得成熟，干扰少
- 买断、无需账号、文件本地

代价是：

- 没有双链、反链、查询、插件生态
- 文档一多，组织能力主要靠文件夹和搜索
- 表格、复杂导出不是它的主战场

**适合**：主要写文章、报告、草稿，不需要知识库能力的人。

### 幕布

强在**大纲和思维导图**：

- 先用层级把想法列出来，再一键转脑图
- 云端同步、分享和团队空间省事
- 适合会议纪要、课程笔记、方案拆解

代价是：

- 不是本地 `.md` 文件工作流
- 不以双链、Dataview、插件/主题生态为核心
- 想长期做知识库，迁移和可组合性不如本地工具

**适合**：主要用大纲/脑图整理思路、需要云端共享的人。

### Morz

强在**本地优先 + 开箱即用**：

- 所见即所得，同时保留 Markdown 源码可编辑
- 文件是普通 `.md`，不锁库、不需要账号
- 双链、反链、块引用、标签、搜索、图谱内置
- 表格支持公式、填充、选区、整格撤销
- Dataview 查询内置，不用先装插件
- HTML / PDF / Word 导出开箱可用
- 图片/表格可视化操作、画廊和自动整理
- 桌面、Android、PWA 覆盖面较完整
- 有插件 SDK、主题市场和公开 registry，但不追求兼容 Obsidian 插件

**适合**：想要 Obsidian 的部分知识库能力，但不想装一堆插件；又想要 Typora 那种直接写的感觉；同时希望文件始终是本地 `.md`。

## 五、Morz 目前不擅长什么

这部分必须说清楚，免得选错：

- **不兼容 Obsidian 插件**。插件需要按 Morz SDK 重写，不能直接搬。
- **没有完整 Dataview 生态**。内置的是常用 DQL 子集和 `dataviewjs`，不是社区 Dataview 的全部能力。
- **没有通用大纲/思维导图**。当前大纲主要服务每日笔记；复杂脑图请用幕布/Logseq。
- **没有内置云同步和实时协作**。当前靠本地文件夹、同步盘或 Git；团队协作不是现阶段重点。
- **没有原生 iOS 版**。iPad/iPhone 走 PWA，能力和原生 App 有差异。
- **macOS / Linux 的 PDF 书签能力不如 Windows/Android**。
- **插件市场和社区规模还在起步**，不能和 Obsidian 比数量。

如果你要的是“插件最多、生态最全、什么都能接”，现在应该选 Obsidian，而不是 Morz。

## 六、其他选择

| 场景 | 更合适的选择 |
|---|---|
| 大纲、思维导图、云端分享 | 幕布 |
| 本地 outliner、块引用、查询 | Logseq |
| 云端协作、数据库视图、团队共享 | Notion |
| 开发者、键盘流、Git、任意语言插件 | VS Code + Markdown 扩展 |
| 纯写作、排版、买断 | Typora |
| 插件化本地知识库 | Obsidian |
| 本地所见即所得 + 内置查询/导出 + 免账号 | Morz |

## 七、从 Obsidian / Typora / 幕布迁过来

- **文件**：Obsidian/Typora 直接用 Morz 打开原来的文件夹，`.md` 原样保留；幕布内容需要先导出。
- **双链**：`[[页面]]`、`[[页面|别名]]`、`[[页面#标题]]`、`[[页面#^块id]]`、`![[嵌入]]` 原生支持。
- **主题**：可以导入 `.css` 主题；Blue Topaz 的设置项也有兼容层。
- **插件**：Obsidian 插件不能直接运行，需要用 Morz SDK 重写；迁移前先确认关键插件是否有替代。
- **Dataview**：常用 `TABLE` / `LIST` / `TASK`、`FROM`、`WHERE`、`SORT`、`GROUP BY`、`LIMIT` 支持；复杂脚本先试跑再迁移。
- **大纲/脑图**：Morz 的大纲模式服务每日笔记，不能替代幕布/Logseq 的通用大纲；需要脑图时保留原工具或导出图片。

## 八、一句话选型

| 你更在意 | 更合适的工具 |
|---|---|
| 纯写作、快捷键手感 | Typora |
| 插件生态、长期知识库 | Obsidian |
| 大纲、脑图、思维导图 | 幕布 / Logseq |
| 本地文件夹、开箱即用、免账号 | Morz |
